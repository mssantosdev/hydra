worktrees across repositories github.com/mssantosdev/hydra

Git gives you one worktree in one repository. A unit of work rarely stays in one.

hydra records which worktree, on which branch, in which repository, belongs to which piece of work, and it records that rather than inferring it from a branch name. It owns identity, layout, freshness and reporting. It never merges, never rebases, never resolves a conflict, and never talks to a forge.

if you are a developer

Read down. Every panel is verbatim output from a real run, including its exit status. Start at install.

if you are an agent

Skip to the contract for the envelope, the 23 error codes and their exit statuses. Then run hydra skill.

§ 01

The workspace

hydra status · hydra list

A workspace is a project holding groups of repositories. Every worktree is a real sibling directory, never hidden inside a .git. This is the whole workspace in one view.

§ 02

Install

one binary, no cgo

It builds with CGO_ENABLED=0, so there is no toolchain to install on the target and no database to provision. State is two YAML files and git itself.

appearance

The default theme is terminal: every colour is an ANSI slot and no background is painted, so hydra inherits the palette your terminal already has rather than imposing one. hydra config set theme hydra selects the fixed palette instead — the one this page is drawn in — and contrib/ carries generated Ghostty and omp themes if you would rather move the terminal to hydra.

Shell integration is optional but wanted. A child process cannot change its parent's directory, so hydra switch prints a path and exits 0 on its own. With the helper installed it changes directory instead.

§ 03

The model

project → group → repo → worktree

Four nouns, and a fifth laid over them. Git data lives once, in a bare repository under .bare/. Every worktree is a plain directory you can cd into.

shop/ # project — one workspace ├── .hydra/ │ ├── config.yaml # the manifest (schema 2) │ └── state.yaml # topic membership, under flock ├── .bare/ │ ├── checkout-api.git # git data, once per repo │ └── storefront-web.git └── services/ # group — a category you choose ├── checkout-api/ # worktree: repo + branch ├── checkout-api-stage/ └── checkout-api-feat-split-tender/ ← topic PAY-4417

A topic is the fifth noun: identity layered over worktrees. It is not a mode and not a lifecycle. Unlabelled worktrees stay first-class forever, and hydra topic attach promotes work you already started, with no migration.

a deliberate refusal

Membership is recorded, never inferred. hydra will not parse feat/PAY-4417-split and guess. Branch naming is a team convention, and a tool that guesses at it is wrong on the day the convention changes.

§ 04

First run

init, repo add

Now register a repository. One command clones the bare repo, records it in the manifest, and materialises a worktree per branch you named.

naming

The unsuffixed directory is the repository's default branch, not the first one you listed in --branches. Order does not decide the layout.

Already have a checkout you don't want to re-clone? hydra repo add <path> --adopt tracks it in place.

§ 05

Interactive routes

the human surface

Run a mutating command with no arguments on a terminal and it asks. The forms are the human-facing route, not a fallback: new, add, sync, config, remove, switch, topic and repo add all have one.

Only prod is offered. hydra filters out branches that already have a worktree, so the list is what you can actually create, not everything that exists.

Reporting has a route of its own. Run hydra status bare on a terminal and it opens a full-screen board instead of printing: browse, filter, and leave with a path. Every refresh re-reads git rather than patching the screen, so it cannot drift from disk. hydra ui survives as a hidden, deprecated alias of the same thing.

↑↓ move   enter print path   y copy path   / filter   d dirty   r refresh   q quit

The board draws on stderr and prints only the chosen path on stdout, which is why cd "$(hydra status)" composes. Quitting with q chooses nothing, prints nothing, and still exits 0.

The filter words are the same ones --filter takes: dirty, behind and branch:<glob>, where * does not cross a /. What you learn here types into a script unchanged, and a test pins the two together.

still open

The board browses and selects; it does not mutate. Acting on a selection still means dropping to sync, remove or add, which have their own forms. Wiring those in is the next increment.

§ 06

A unit of work

start, topic, run

One branch, several repositories, one command. The topic id is whatever you already use: a ticket, an incident, a name.

Then act on the whole topic at once. Everything after -- is handed to exec directly. There is no implicit shell, so no quoting surprises. Pass -- sh -c '…' when you want one.

Selectors intersect: --topic, --repos, --group, --all and --filter dirty|behind|branch:<glob> narrow together rather than competing. A selector that matches nothing is an empty result, not a silent everything.

§ 07

Staying current

sync, and dated freshness
the one thing to understand

hydra does not fetch to answer a query. So behind: 0 means “as of the last fetch”, and every count is stamped with upstream_as_of taken from the bare repo's FETCH_HEAD. A dated answer beats a confident one.

hydra sync is where fetching happens. On a terminal it shows you what has updates and lets you choose.

x toggle   ↑↓ move   / filter   enter submit   ctrl+a select none

A dirty worktree is treated differently, and visibly so: its marker is • where a clean one is ✓, and it is not pre-selected.

Verified rather than asserted: with a local edit present and the branch one commit behind, the stash path fast-forwarded the worktree and the edit was still there afterwards.

One unreachable remote does not stop the reachable ones from pulling, and the failure is still reported. The exit status is derived from the envelope, so a command cannot print partial and exit 0.

§ 08

The contract

for anything that parses

One envelope, on stdout, per invocation. --output json is implied whenever stdout is not a terminal, so a pipe already gets JSON without asking.

Branch on error.code, never on message wording. Codes are stable across versions; messages are not. There is no exit field in the envelope; the process status carries it.

An unrecognised command answers with the whole surface and a next step rather than a stack trace:

§ 09

For agents

hydra skill

hydra ships its own agent contract. Print it and hand it over; it is versioned with the binary, so it cannot drift from the tool the way a pasted prompt does.

Its invariants, verbatim, because they are what makes probing unnecessary:

#invariant
1--output json (default when stdout is not a terminal) emits one envelope. Never scrape text.
2Branch on error.code, never on message wording. Codes are stable; messages are not.
3Every command is convergent: doing it twice is a no-op that exits 0, reported as skipped.
4Nothing is inferred from a branch name. Topic membership is recorded, never guessed.
5A missing value is needs_input (exit 7) naming it in details.missing. hydra never blocks on a prompt when output is machine-readable.
6A handle matching several worktrees is an error, never a silent first match.
7hydra commands --output json publishes the whole surface and the code→exit table.
why this is safe in a loop

The destructive operations are not in hydra's vocabulary. It cannot merge, rebase, resolve a conflict or push. The worst a wrong call does is create or remove a worktree, and removal refuses on uncommitted work with exit 5.

§ 10

Recovery

doctor, prune, repo restore

Interrupted clones, worktrees deleted behind hydra's back, stale registrations. doctor audits the manifest against the disk and says what it can repair.

A warning is not a failure: a dirty worktree is your work, correctly left alone. Failures get --fix, and each one names the exact command that repairs it.

commandwhat it is for
doctor --fixRepair what is mechanically repairable; report the rest with a runnable command.
pruneDrop registrations whose worktrees are gone. Leaves files alone.
repo restoreRebuild repositories from the manifest alone: the recovery path after a lost clone.
apply -Read hydra list --output json on stdin and recreate that workspace elsewhere.

apply is the pair to list: the output of one is the input of the other, which is how a workspace gets reproduced on another machine.
